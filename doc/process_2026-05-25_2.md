# ADMX help в workspace

Дата: `2026-05-25`

## Что описывает документ

Документ фиксирует, как в текущем UI работает вывод `help` для ADMX-разделов в блок:

```text
.workspace .gp__list-children-help .content
```

Важно различать два help-блока:

- `.gp__list-children-help .content` — помощь для экранов-папок в workspace;
- `.gp__admx-help .gp__admx-text-help .gp__admx-content` — помощь внутри экрана конкретной ADMX-политики.

## Краткий итог

Для `.gp__list-children-help .content` данные берутся из свойства `help` выбранного узла дерева.

Путь данных такой:

```text
API.getPolicy('/')
  -> buildTreeViewList(policyData)
  -> convertPolicySection(...)
  -> узлы дерева
  -> treeViewState.renderSelectedItem(...)
  -> renderFolderTemplate({ help: item.help })
  -> renderHelpBlock(...)
  -> .gp__list-children-help .content
```

Если у выбранной папки `item.help` есть строка, она выводится в `.content`. Если `item.help` равен `undefined`, выводится временный `HELP_PLACEHOLDER` из `folder-template.js`. Если `item.help === ''`, help-блок не создается.

## Откуда приходят ADMX-данные

Дерево политик загружается в `chain/js/components/tree-view/tree-view-list-data.js`.

Функция `loadTreeViewList()`:

1. ожидает `nameGpt` через `API.waitForNameGpt()`;
2. вызывает `API.getPolicy('/')`;
3. передает полученный `policyData` в `buildTreeViewList(policyData)`.

`API.getPolicy()` находится в `chain/js/util/API.js`. Он отправляет RPC-команду:

```js
entity: 'gpo',
method: 'get_policy',
args: [path || '/']
```

Ожидаемый результат описан в комментарии API как структура:

```js
{
  meta,
  Machine,
  User
}
```

Секции `Machine` и `User` содержат ADMX-категории и политики. Пример такой структуры есть в локальных файлах `policy-ru.js` и `policy-en.js`: у категорий встречается поле `help`, у политик также есть `help`, а внутри `header` есть `explainText` и `supportedOn`.

## Как ADMX попадает в дерево

В `buildTreeViewList(policyData)` ADMX-ветки строятся так:

```js
const machineCategories = convertPolicySection(policyData.Machine, 'Machine');
const userCategories = convertPolicySection(policyData.User, 'User');
```

Затем `machineCategories` вставляются в:

```text
Machine -> Administrative Templates
```

а `userCategories` вставляются в:

```text
User -> Administrative Templates
```

Часть верхних папок создается вручную в `tree-view-list-data.js` и уже содержит `help`:

- `Local group policies templates`;
- `Machine level policies`;
- `Machine administrative templates`;
- `Preferences policies.`;
- `Policies that set system settings.`;
- `User level policies`.

Эти строки не приходят из ADMX. Они захардкожены в UI-дереве.

## Как работает конвертер ADMX

ADMX-категории конвертируются в `chain/js/components/tree-view/policy-converter.js`.

`convertPolicySection(section, sectionClass)` берет `section.categories` и для каждой категории вызывает `convertPolicyCategory(...)`.

`convertPolicyCategory(categoryNode, ctx)`:

- пропускает пустые категории без `inherited` и без `policies`;
- рекурсивно обходит `categoryNode.inherited`;
- для каждой политики из `categoryNode.policies` создает file-узел с `template: 'admx'`;
- возвращает folder-узел категории.

Узел политики получает:

```js
{
  title: policy.displayName,
  type: 'file',
  icon: 'ico-file',
  policyKey: key,
  policyData: policy,
  template: 'admx',
  admxTreePath: ...
}
```

То есть все исходные данные политики, включая `policy.help`, `policy.header.explainText` и `policy.header.supportedOn`, сохраняются внутри `item.policyData`.

## Передача help для ADMX-категорий

В исходных ADMX-данных у категорий есть поле `help`. Например в `policy-ru.js`:

```js
{
  "category": "Система ALT",
  "help": "Настройки решений на базе операционной системы «Альт».",
  "policies": {},
  "inherited": [...]
}
```

`convertPolicyCategory(...)` переносит `categoryNode.help` в возвращаемый folder-узел:

```js
return {
  title: categoryNode.category,
  type: 'folder',
  opened: false,
  icon: 'ico-folder',
  help: categoryNode.help,
  children: children.length > 0 ? children : undefined,
};
```

Поэтому для ADMX-категорий, созданных конвертером, `item.help` содержит текст из `get_policy`, если сервер вернул поле `help`. При выборе такой ADMX-папки `.gp__list-children-help .content` показывает реальный help категории. Если поле `help` отсутствует, `renderHelpBlock(...)` использует `HELP_PLACEHOLDER`.

## Как рендерится `.gp__list-children-help .content`

За папочный workspace отвечает `chain/js/components/templates/folder-template.js`.

При выборе folder-узла `treeViewState.renderSelectedItem(...)` вызывает:

```js
renderFolderTemplate({
  children: item.children || [],
  help: item.help,
  isHelpOpen: this.isHelpOpen,
  onItemClick: ...
})
```

`renderFolderTemplate(...)` передает `help` дальше:

```js
const helpBlock = renderHelpBlock({
  help,
  isOpen: isHelpOpen,
});
```

`renderHelpBlock(...)` работает так:

```js
if (help === '') {
  return null;
}

const helpText = help === undefined
  ? HELP_PLACEHOLDER
  : help;
```

И затем создает DOM:

```js
createElement('div', {
  className: ['gp__list-children-help', isOpen ? 'is-open' : null],
  children: [
    createElement('div', { className: 'title', text: 'Помощь:' }),
    createElement('div', { className: 'content', text: helpText }),
  ],
})
```

Именно `helpText` становится текстом `.workspace .gp__list-children-help .content`.

## Как открывается и закрывается help

Состояние help хранится в `treeViewState.isHelpOpen`.

Кнопка помощи доступна, если выбран:

- folder-узел;
- ADMX file-узел, то есть `item.type === 'file'` и `item.template === 'admx'`.

Это проверяется в `isHelpToggleAvailable()`.

При клике по кнопке вызывается `toggleHelp()`, который меняет `isHelpOpen`. Потом `syncHelpBlockState()` переключает класс `is-open` у найденных help-блоков:

```js
workspaceEl.querySelectorAll('.gp__list-children-help, .gp__admx-help')
```

CSS для `.workspace .gp__list-children-help` задает закрытое состояние через `width: 0`, а открытое состояние через класс `.is-open`:

```css
.workspace .gp__list-children-help.is-open {
  width: 432px;
  padding: 20px;
}
```

## Что происходит при выборе ADMX-политики

ADMX-политика является file-узлом с `template: 'admx'`. Для нее `renderSelectedItem(...)` вызывает `renderAdmxTemplate(...)`, а не `renderFolderTemplate(...)`.

В этом режиме выводится другой help-блок:

```text
.gp__admx-help
```

Внутри него:

- `policyHeader.supportedOn` выводится в блок `Поддерживается на:`;
- `policyHeader.explainText` выводится в блок `Помощь:`;
- текст помощи форматируется через `formatExplainText(policyHeader.explainText)`.

То есть для экрана конкретной ADMX-политики основным источником help-текста является:

```js
item.policyData.header.explainText
```

а не `.gp__list-children-help .content`.

## Итог по источникам help

| Экран | DOM-блок | Источник данных |
| --- | --- | --- |
| Верхние папки дерева | `.gp__list-children-help .content` | `help`, заданный вручную в `tree-view-list-data.js` |
| ADMX-категория | `.gp__list-children-help .content` | `categoryNode.help` из `get_policy` |
| ADMX-политика | `.gp__admx-text-help .gp__admx-content` | `item.policyData.header.explainText` |
| ADMX-политика, поддерживаемые версии | `.gp__admx-supported .gp__admx-content` | `item.policyData.header.supportedOn` |
| Отсутствующий folder help | `.gp__list-children-help .content` | `HELP_PLACEHOLDER` |
| `help === ''` | help-блок не создается | Пустая строка специально отключает блок |

## Минимальная схема данных

Для папочного help нужен такой узел дерева:

```js
{
  title: 'LAPS',
  type: 'folder',
  icon: 'ico-folder',
  children: [...],
  help: 'Настройка параметров LAPS.'
}
```

Для ADMX-политики нужен такой узел:

```js
{
  title: policy.displayName,
  type: 'file',
  template: 'admx',
  policyData: {
    help: '...',
    header: {
      explainText: '...',
      supportedOn: '...'
    }
  }
}
```

`policyData.help` сейчас сохраняется в узле политики, но экран ADMX-политики использует `policyData.header.explainText`.
