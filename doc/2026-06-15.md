# Group Policy Preferences — Shortcuts: серверная часть и API

> Дата: 2026-06-15
> Область: только серверная часть (RPC → DBus → `GPPrefsWorker` → `Shortcuts.xml` в SYSVOL).
> LocalStorage-клиент в `plugin/ui/.../mainLocalStorage/shortcuts.js` в этом документе **не рассматривается**.

## 1. Архитектура энд-ту-энд

```
[Клиент UI / CLI]
       │  JSON-RPC (FreeIPA Web API)
       ▼
[ipaserver/plugins/gpo.py]
   gpo_save_preference / gpo_get_preferences / gpo_delete_preference
       │  self.api.Object.gpo._call_gpuiservice_method(...)
       ▼
[gpui_service/service.py]   GPUIService (DBus: org.altlinux.GPUIService)
   save_preference / get_preferences / delete_preference
       │  self.data_store.<method>(...)
       ▼
[gpui_service/datastore.py]  GPODataStore (блокировка self.lock, bump GPT.INI)
   _save_preference_unlocked / _get_preferences_unlocked / _delete_preference_unlocked
       │  utils.resolve_gpo_path(...) → валидация пути
       ▼
[gpui_service/gpprefs.py]    GPPrefsWorker
   save_preference / read_preferences / delete_preference
       │  генерация/парсинг XML по MS-GPPREF
       ▼
 SYSVOL:  <sysvol>/<gpo>/<Machine|User>/Preferences/Shortcuts/Shortcuts.xml
```

Ключевые файлы серверной части:

| Слой | Файл | Роль |
|---|---|---|
| RPC | `plugin/ipaserver/plugins/gpo.py:942-1156` | Команды FreeIPA `gpo_*_preference` |
| DBus | `gpui_service/service.py:364-443` | Тонкая обёртка над data_store |
| Мост | `gpui_service/datastore.py:896-1016` | Резолв путей + версионирование GPT.INI |
| Worker | `gpui_service/gpprefs.py` | Генерация/парсинг XML, валидация |
| Entry | `gpui_service/daemon.py`, `gpuiservice.py` | Запуск DBus-сервиса |

## 2. Поверхность API (3 команды)

### 2.1 `gpo_save_preference`
`plugin/ipaserver/plugins/gpo.py:942`

Аргументы:
- `name_gpt` — путь/имя GPO относительно sysvol (напр. `{GUID}` или `gpt1test`)
- `target` — `Machine` | `User`
- `pref_type` — для ярлыков строка `"Shortcuts"`
- `value` — **JSON-строка** со свойствами ярлыка + общие `_`-атрибуты
- `uid?` — UID существующего ярлыка для **обновления**; пусто/отсутствует → **создание**

Возвращает: `{ summary, result: { success, message, uid, new_version? } }`
При успехе синхронизирует версию в LDAP через `_update_ldap_version()`.

### 2.2 `gpo_get_preferences`
`plugin/ipaserver/plugins/gpo.py:1020`

Аргументы: `name_gpt`, `target`, `pref_type?` (пусто = все типы).
Возвращает: `{ summary, result: { <pref_type>: [ <pref_dict>, ... ] } }`

### 2.3 `gpo_delete_preference`
`plugin/ipaserver/plugins/gpo.py:1083`

Аргументы: `name_gpt`, `target`, `pref_type`, `uid`.
Возвращает: `{ summary, success: bool }`. При успехе инкрементирует версию GPT.INI и LDAP.

## 3. Схема свойств Shortcuts (серверный канон)

`gpui_service/gpprefs.py:176-179` (`PROPERTY_SCHEMAS['Shortcuts']`):

| Поле | Обяз. | Тип / значения | Назначение |
|---|---|---|---|
| `targetType` | да | `FILESYSTEM` \| `URL` \| `SHELL` | Тип цели ярлыка |
| `targetPath` | да | string (путь экранируется) | На что указывает ярлык |
| `shortcutPath` | да | string (путь экранируется) | Куда положить `.lnk`/`.desktop` |
| `action` | нет | `U`\|`C`\|`R`\|`D` | Update/Create/Replace/Delete |
| `arguments` | нет | string | Аргументы запуска |
| `startIn` | нет | string (путь) | Рабочий каталог |
| `iconPath` | нет | string (путь) | Путь к иконке |
| `iconIndex` | нет | int | Индекс иконки |
| `shortcutKey` | нет | int 0-255 | Горячая клавиша |
| `window` | нет | string | Тип окна (`1`=normal и т.п.) |
| `comment` | нет | string | Комментарий ярлыка |
| `pidl` | нет | string | PIDL (Windows shell) |
| `disabled` | нет | bool | Отключить элемент |

> Пути из `PATH_PROPERTIES['Shortcuts'] = {targetPath, shortcutPath, startIn, iconPath}`
> прогоняются через `_escape_path()` — любая серия `\` схлопывается в `\\` для XML-атрибута.

Общие атрибуты (в JSON с префиксом `_`, `COMMON_ATTR_KEYS`, `gpprefs.py:287`):

| Ключ JSON | XML-атрибут | Тип | По умолч. |
|---|---|---|---|
| `_bypassErrors` | `bypassErrors` | bool | `1` |
| `_userContext` | `userContext` | bool / `"user"`\|`"machine"` | `0` |
| `_removePolicy` | `removePolicy` | bool | `0` |
| `_desc` | `desc` | string | — |
| `_status` | `status` | string/int | `name` |
| `_image` | `image` | int | `0` |
| `_filters` | `<Filters>` | `{operator, conditions:[{type,...}]}` | — |

`name` (отображаемое имя ярлыка) **не передаётся клиентом** — оно автоматически выводится из `basename(shortcutPath)` (`NAME_DERIVE_MAP['Shortcuts']`, `gpprefs.py:277`).

CLSID-константы ярлыков (`gpprefs.py:58`, `72`):
- Outer `Shortcuts` → `{872ECB34-B2EC-401b-A585-D32574AA90EE}`
- Inner `Shortcut` → `{4F2F7C55-2790-433e-8127-0739D1CFA327}`
- Файл: `Shortcuts.xml` (`FILE_NAME_MAP['Shortcuts']`, `gpprefs.py:148`)

### 3.1 Вкладка «Общие» (GPMC Common tab): общие флаги элемента

В GPMC у каждого элемента preferences есть вкладка **Common** с набором чекбоксов, **единым для всех 11 типов**. Клиентский рендер этих полей — `plugin/ui/grouppolicy/js/components/workspace/preferences-template-common.js:9-139`. На стороне сервера флаги передаются внутри `value` (ключи с префиксом `_`, множество `COMMON_ATTR_KEYS`, `gpprefs.py:287`) и сохраняются как XML-атрибуты на самом внутреннем элементе (`<Shortcut>`/`<File>`/`<Folder>`/…), а **не** внутри `<Properties>`.

| Чекбокс GPMC (RU) | JSON-ключ в `value` | XML-атрибут | Тип | По умолч. | UI data-name |
|---|---|---|---|---|---|
| Остановить обработку элементов при ошибке | `_bypassErrors` (**инверт.**) | `bypassErrors` | bool | `1` | `stopOnErrorCheckBox` |
| Выполнять в контексте безопасности текущего пользователя (опция пользовательских политик) | `_userContext` | `userContext` | bool / `"user" \| "machine"` | `0` | `userContextCheckBox` |
| Удалить элемент, если больше не применим | `_removePolicy` | `removePolicy` | bool | `0` | `removeThisCheckBox` |
| Применить только один раз | ⚠ **не реализовано** | — | — | — | `applyOnceCheckBox` (disabled) |
| Выбор элементов (Item-level targeting) | `_filters` | `<Filters>` | `{operator, conditions}` | — | `itemLevelCheckBox` (disabled) |
| Описание | `_desc` | `desc` | string | — | `description` (textarea) |

> `name`/`status`/`image` (`_status`, `_image`) также входят в `COMMON_ATTR_KEYS`, но это не чекбоксы вкладки Common, а служебные атрибуты элемента (см. таблицу в §3).

#### Семантика и нюансы

**`_bypassErrors` — инвертированная логика.** Имя XML-атрибута означает «bypass (пропускать) ошибки», а чекбокс в GPMC имеет противоположный смысл:
- чекбокс «Остановить…» **снят** (по умолчанию) → `bypassErrors="1"` → при ошибке элемента обработка остальных продолжается;
- чекбокс «Остановить…» **установлен** → `bypassErrors="0"` → при ошибке дальнейшая обработка прекращается.

Иначе говоря, на запись выполняется `_bypassErrors = NOT stopOnError`, а на чтение — наоборот. Если ключ не передан, сервер принудительно пишет `bypassErrors="1"` (`gpprefs.py:932-933`).

**`_userContext`** дополнительно принимает строковые синонимы: `"user"` → `true`, `"machine"` → `false` (`gpprefs.py:926-930`). Имеет смысл только для политик в области `User`; для `target="Machine"` всегда `0`.

**`_removePolicy`** — удалять элемент с машины, когда GPO перестаёт применять (GPMC «Remove this item when it is no longer applicable»).

**`applyOnceCheckBox` («Применить только один раз»)** в текущем UI заблокирован (`disabled:'disabled'`, `preferences-template-common.js:83`), а на сервере соответствующего ключа в `COMMON_ATTR_KEYS` **нет** — флаг не сохраняется и не обрабатывается. В нативной MS-GPPREF «apply once» не является XML-атрибутом: поведение реализуется клиентским CSE через локальный маркер успешного применения.

**`itemLevelCheckBox` («Выбор элементов»)** в UI тоже заблокирован, но серверный механизм item-level targeting **реализован** через `_filters` (см. таблицу общих атрибутов в §3 и §7.12 п.7). Чтобы задать таргетинг, передайте в `value` объект `_filters`; сам чекбокс в GPMC лишь открывает графический редактор фильтров и для API не нужен.

#### Как передать (создание/обновление)

Любой флаг добавляется включением соответствующего `_`-ключа в `value` (вместе с типоспецифичными полями):

```json
{
  "targetType": "FILESYSTEM",
  "targetPath": "C:\\App\\app.exe",
  "shortcutPath": "%DesktopDir%\\App.lnk",

  "_bypassErrors": false,
  "_userContext": "user",
  "_removePolicy": true,
  "_desc": "Ярлык приложения App",
  "_filters": { "operator": "AND", "conditions": [] }
}
```

Разбор — в `_extract_common_attrs` (`gpprefs.py:308`): всё из `COMMON_ATTR_KEYS` уходит в атрибуты элемента, остальное — в `<Properties>` (и проходит типовую валидацию). Неизвестные свойства отбрасываются как «unknown property».

#### Как хранится (XML)

Три булевых флага пишутся как атрибуты **самого элемента** через `_bool_to_int` → `"0"`/`"1"` (`gpprefs.py:923-933`); `desc`/`status`/`image` — там же строкой/числом:

```xml
<Shortcut clsid="{4F2F7C55-2790-433e-B7E7-0739D1CFA327}"
          name="App.lnk"
          uid="{...}"
          changed="2026-06-15 14:00:00"
          desc="Ярлык приложения App"
          status="App.lnk"
          image="0"
          bypassErrors="0"
          userContext="1"
          removePolicy="1">
  <Properties .../>
  <Filters bool="AND"/>
</Shortcut>
```

#### Как читается (ответ `gpo_get_preferences`)

В распарсенном элементе флаги возвращаются **на верхнем уровне** (вне `properties`) булевым значением (`gpprefs.py:1195-1207`):

```json
{
  "type": "Shortcuts",
  "uid": "{...}",
  "name": "App.lnk",
  "desc": "Ярлык приложения App",
  "status": "App.lnk",
  "image": 0,
  "bypassErrors": false,
  "userContext": true,
  "removePolicy": true,
  "properties": { "...": "..." },
  "filters": { "operator": "AND", "conditions": [] }
}
```

> На чтение инверсия сохраняется: `bypassErrors:false` = чекбокс «Остановить обработку» **установлен**. При подстановке в UI-форму значение нужно инвертировать обратно перед установкой чекбокса `stopOnErrorCheckBox`.

#### Пошаговое руководство (create → edit → read)

> Вкладка «Общие» в UI — это `#tab-general` (`preferences-view-template.js:276-282`), рендерится `renderPreferencesCommonTemplate()`. Чекбоксы собираются в объект `commonData` через `collectPreferencesFromTabBasic()` (`create-preference.js:100`). **Важно:** UI-имена полей (`data-name`) и серверные JSON-ключи (`_`-префикс) **разные** — нужен mapping.

**Шаг 0. Соответствие UI ↔ API**

Каждый чекбокс в форме (атрибут `data-name`) прямо отображается в один `_`-ключ серверного `value`:

| UI `data-name` | Тип поля UI | JSON-ключ в `value` | XML-атрибут | Комментарий |
|---|---|---|---|---|
| `stopOnErrorCheckBox` | checkbox | `_bypassErrors` | `bypassErrors` | ⚠ **инверсия** значений |
| `userContextCheckBox` | checkbox | `_userContext` | `userContext` | прямое соответствие |
| `removeThisCheckBox` | checkbox | `_removePolicy` | `removePolicy` | прямое соответствие |
| `applyOnceCheckBox` | checkbox (**disabled**) | — нет — | — | не реализовано |
| `itemLevelCheckBox` | checkbox (**disabled**) | `_filters` | `<Filters>` | API есть, UI-чекбокс декоративный |
| `description` | textarea | `_desc` | `desc` | прямое соответствие |

**Шаг 1. Таблица истинности для `bypassErrors` (инверсия)**

Это единственный флаг с инверсией — все остальные (`userContext`, `removePolicy`, `desc`) передаются 1-в-1:

| Чекбокс «Остановить при ошибке» | `_bypassErrors` в JSON-запросе | XML `bypassErrors` | Поведение CSE |
|---|---|---|---|
| ☐ **снят** (по умолчанию) | `true` (или ключ опущен) | `"1"` | при ошибке элемента — **продолжать** остальные |
| ☑ **установлен** | `false` | `"0"` | при ошибке элемента — **остановить** обработку |

> Мнемоника: имена разные, потому что смотрят с разных сторон. Чекбокс = «остановить?», атрибут = «пропускать ошибки?». `stopOnError = NOT bypassErrors`.

**Шаг 2. СОЗДАНИЕ элемента с общими флагами**

Вызов `gpo_save_preference` с `uid=""`. Общие флаги — это `_`-ключи **в том же объекте `value`**, что и типоспецифичные поля:

```
name_gpt  = "{31B2F340-016D-11D2-945F-00C04FB984F9}"
target    = "User"
pref_type = "Shortcuts"
uid       = ""
```

`value` — допустим, все три рабочих чекбокса включены, и мы задаём описание:
```json
{
  "targetType": "FILESYSTEM",
  "targetPath": "C:\\App\\app.exe",
  "shortcutPath": "%DesktopDir%\\App.lnk",

  "_bypassErrors": false,
  "_userContext": true,
  "_removePolicy": true,
  "_desc": "Ярлык приложения App"
}
```

> `_bypassErrors: false` = чекбокс «Остановить» ☑ установлен (инверсия!).
> `_userContext: true` = чекбокс «В контексте пользователя» ☑ установлен.
> `_removePolicy: true` = чекбокс «Удалить, если не применим» ☑ установлен.

Ответ: `{ "success": true, "uid": "{NEW-GUID}", "new_version": 2 }`.

**Шаг 3. ЧТЕНИЕ обратно — какие ключи вернуть в форму**

Вызов `gpo_get_preferences` → флаги приходят **на верхнем уровне** элемента (не внутри `properties`):

```json
{
  "type": "Shortcuts",
  "uid": "{NEW-GUID}",
  "name": "App.lnk",
  "desc": "Ярлык приложения App",
  "bypassErrors": false,
  "userContext": true,
  "removePolicy": true,
  "properties": { "targetType": "FILESYSTEM", "...": "..." },
  "filters": { "operator": "AND", "conditions": [] }
}
```

Чтобы заполнить UI-форму из этого ответа, каждую пару «ответ → чекбокс» нужно преобразовать:

| Поле ответа | Значение в ответе | → установить в UI |
|---|---|---|
| `bypassErrors` | `false` | `stopOnErrorCheckBox.checked = true` (инверсия!) |
| `bypassErrors` | `true` | `stopOnErrorCheckBox.checked = false` |
| `userContext` | `true` | `userContextCheckBox.checked = true` (прямо) |
| `removePolicy` | `true` | `removeThisCheckBox.checked = true` (прямо) |
| `desc` | `"текст"` | `description.value = "текст"` (прямо) |

> Только `bypassErrors` требует инверсии при загрузке в форму; три остальных поля подставляются напрямую.

**Шаг 4. РЕДАКТИРОВАНИЕ общих флагов**

Тот же `gpo_save_preference`, но с `uid` существующего элемента. Передаёте **весь** `value` заново (и типоспецифичные, и общие поля) — частичного обновления только общих флагов нет, `value` заменяется целиком (`_update_collection`, `gpprefs.py:1093`):

```
uid = "{NEW-GUID}"        # тот же, из шага 2
```

`value` — например, отключаем «Остановить» и убираем описание:
```json
{
  "targetType": "FILESYSTEM",
  "targetPath": "C:\\App\\app.exe",
  "shortcutPath": "%DesktopDir%\\App.lnk",

  "_bypassErrors": true,
  "_userContext": true,
  "_removePolicy": true,
  "_desc": ""
}
```

> `_bypassErrors: true` = чекбокс «Остановить» ☐ снят (инверсия). Остальные поля нужно повторить, иначе они будут потеряны. `changed` перезапишется серверным временем автоматически.

**Шаг 5. Полный XML после шага 2**

Все три флага — атрибуты элемента `<Shortcut>` (не `<Properties>`):
```xml
<Shortcut clsid="{4F2F7C55-2790-433e-8127-0739D1CFA327}"
          name="App.lnk"
          uid="{NEW-GUID}"
          changed="2026-06-15 17:17:28"
          desc="Ярлык приложения App"
          bypassErrors="0"
          userContext="1"
          removePolicy="1">
  <Properties targetType="FILESYSTEM"
              targetPath="C:\\App\\app.exe"
              shortcutPath="%DesktopDir%\\App.lnk"/>
  <Filters bool="AND"/>
</Shortcut>
```

> ⚠ **Текущее состояние UI.** В коде UI (`create-preference.js:91-143`) сохранение идёт в **localStorage** под ключом `shortcuts` в формате `{ basic: {...}, common: {...} }`, где `common` содержит `data-name`-ключи (`stopOnErrorCheckBox`, `userContextCheckBox`, ...). Обёртки для отправки общих флагов на сервер (`_bypassErrors` и т.д.) в `plugin/ui/.../util/API.js` **пока нет** — требуется mapping-слой, преобразующий `stopOnErrorCheckBox ↔ _bypassErrors` (с инверсией) и т.д. См. §9 п.8.

## 4. Полный пример: жизненный цикл ярлыка

Ниже — конкретные JSON, отправляемые в `value` и получаемые из RPC, для сквозного сценария **create → read → update → delete**.

### 4.1 CREATE — создание ярлыка

**Вызов:** `gpo_save_preference`

Аргументы:
```
name_gpt   = "{31B2F340-016D-11D2-945F-00C04FB984F9}"
target     = "Machine"
pref_type  = "Shortcuts"
uid        = ""              # пусто => создать новый
value      = <JSON ниже>
```

`value` (запрос):
```json
{
  "targetType": "FILESYSTEM",
  "targetPath": "C:\\Program Files\\MyApp\\app.exe",
  "shortcutPath": "%DesktopDir%\\MyApp.lnk",
  "action": "C",
  "arguments": "--minimized",
  "startIn": "C:\\Program Files\\MyApp",
  "iconPath": "C:\\Program Files\\MyApp\\app.exe",
  "iconIndex": "0",
  "window": "1",
  "shortcutKey": "0",
  "comment": "Запуск MyApp",
  "disabled": false,

  "_bypassErrors": true,
  "_userContext": false,
  "_removePolicy": false,
  "_desc": "Ярлык для приложения MyApp",
  "_status": "0",
  "_image": 0,
  "_filters": { "operator": "AND", "conditions": [] }
}
```

Ответ (успех):
```json
{
  "summary": "{\"success\": true, \"message\": \"Successfully saved Shortcuts preference to .../Shortcuts.xml\", \"uid\": \"{A1B2C3D4-E5F6-7890-1234-567890ABCDEF}\", \"new_version\": 4}",
  "result": {
    "success": true,
    "message": "Successfully saved Shortcuts preference to /var/lib/freeipa/sysvol/.../Machine/Preferences/Shortcuts/Shortcuts.xml",
    "uid": "{A1B2C3D4-E5F6-7890-1234-567890ABCDEF}",
    "new_version": 4
  }
}
```
> `uid` генерируется сервером (`uuid.uuid4()` в верхнем регистре в `{...}`). `new_version` — инкремент `General` в `GPT.INI` (см. `_update_gpo_version`, datastore.py:926). `name` автоматически = `MyApp.lnk`.

Полученный на диске `Shortcuts.xml`:
```xml
<?xml version="1.0" encoding="utf-8"?>
<Shortcuts clsid="{872ECB34-B2EC-401b-A585-D32574AA90EE}">
  <Shortcut clsid="{4F2F7C55-2790-433e-8127-0739D1CFA327}"
            name="MyApp.lnk"
            uid="{A1B2C3D4-E5F6-7890-1234-567890ABCDEF}"
            changed="2026-06-15 14:00:00"
            status="0"
            image="0"
            desc="Ярлык для приложения MyApp"
            bypassErrors="1"
            userContext="0"
            removePolicy="0">
    <Properties targetType="FILESYSTEM"
                targetPath="C:\\Program Files\\MyApp\\app.exe"
                shortcutPath="%DesktopDir%\\MyApp.lnk"
                action="C"
                arguments="--minimized"
                startIn="C:\\Program Files\\MyApp"
                iconPath="C:\\Program Files\\MyApp\\app.exe"
                iconIndex="0"
                window="1"
                shortcutKey="0"
                comment="Запуск MyApp"
                disabled="0"/>
    <Filters bool="AND"/>
  </Shortcut>
</Shortcuts>
```

### 4.2 READ — чтение ярлыков

**Вызов:** `gpo_get_preferences`

Аргументы:
```
name_gpt  = "{31B2F340-016D-11D2-945F-00C04FB984F9}"
target    = "Machine"
pref_type = "Shortcuts"   # пусто => все типы
```

Ответ (парсинг XML `_parse_preference_element`, gpprefs.py:1173):
```json
{

  "result": {

      {
        "type": "Shortcuts",
        "uid": "{A1B2C3D4-E5F6-7890-1234-567890ABCDEF}",
        "name": "MyApp.lnk",
        "changed": "2026-06-15 14:00:00",
        "status": 0,
        "image": 0,
        "desc": "Ярлык для приложения MyApp",
        "bypassErrors": true,
        "userContext": false,
        "removePolicy": false,
        "properties": {
          "targetType": "FILESYSTEM",
          "targetPath": "C:\\Program Files\\MyApp\\app.exe",
          "shortcutPath": "%DesktopDir%\\MyApp.lnk",
          "action": "C",
          "arguments": "--minimized",
          "startIn": "C:\\Program Files\\MyApp",
          "iconPath": "C:\\Program Files\\MyApp\\app.exe",
          "iconIndex": 0,
          "window": "1",
          "shortcutKey": 0,
          "comment": "Запуск MyApp",
          "disabled": false
        },
        "filters": { "operator": "AND", "conditions": [] }

```
> При чтении числовые атрибуты (`iconIndex`, `shortcutKey`, `status`, `image`) приводятся к `int`, булевы (`disabled`) — к `bool`. При `pref_type=""` в `result` вернутся все непустые типы.

### 4.3 UPDATE — изменение ярлыка

Тот же `gpo_save_preference`, но передаём `uid` существующего элемента:
```
name_gpt  = "{31B2F340-016D-11D2-945F-00C04FB984F9}"
target    = "Machine"
pref_type = "Shortcuts"
uid       = "{A1B2C3D4-E5F6-7890-1234-567890ABCDEF}"   # тот самый
value     = { ...новые свойства... }
```

`value` (запрос) — например, сменим `action` на `U` и аргументы:
```json
{
  "targetType": "FILESYSTEM",
  "targetPath": "C:\\Program Files\\MyApp\\app.exe",
  "shortcutPath": "%DesktopDir%\\MyApp.lnk",
  "action": "U",
  "arguments": "--verbose",
  "comment": "Запуск MyApp (update)"
}
```
Логика обновления (`_update_collection`, gpprefs.py:1093): по совпадению `uid` старый `<Shortcut>` удаляется, новый дописывается в конец. `changed` перезаписывается текущим временем сервера. Формат `uid` проверяется регэкспом GUID (gpprefs.py:1001), иначе `{success:false}`.

Ответ:
```json
{ "result": { "success": true, "uid": "{A1B2C3D4-...}", "new_version": 5 } }
```

### 4.4 DELETE — удаление ярлыка

**Вызов:** `gpo_delete_preference`

Аргументы:
```
name_gpt  = "{31B2F340-016D-11D2-945F-00C04FB984F9}"
target    = "Machine"
pref_type = "Shortcuts"
uid       = "{A1B2C3D4-E5F6-7890-1234-567890ABCDEF}"
```

Ответ:
```json
{
  "summary": "Preference deleted: Shortcuts {31B2F340-...} (uid: {A1B2C3D4-...})",
  "success": true
}
```
Поведение (`delete_preference`, gpprefs.py:1283): элемент с matching `uid` удаляется; если элементов не осталось — файл `Shortcuts.xml` **удаляется целиком**, иначе перезаписывается с pretty-print. При успехе версия `GPT.INI` снова инкрементируется и пишется в LDAP. При отсутствии UID — `success:false`, файл не трогается.

## 5. Валидация (серверная, `_validate_shortcuts_properties`, gpprefs.py:513)

Перед записью XML проверяется:
- `targetType`, `targetPath`, `shortcutPath` — обязательны и непусты;
- `targetType ∈ {FILESYSTEM, URL, SHELL}`;
- `action ∈ {U,C,R,D}`;
- `shortcutKey` — целое 0-255;
- `disabled` — boolean (`true/false/0/1/yes/no/on/off`).

При ошибке валидации → `{success:false, message:"<текст>", uid:""}`, файл не пишется. Неизвестные поля отсекаются (`_create_properties_element` пропускает всё не из `allowed`).

## 6. Размещение файла в SYSVOL и версионирование

Путь: `<sysvol_path>/<name_gpt>/<Machine|User>/Preferences/Shortcuts/Shortcuts.xml`
(`_get_xml_file_path`, gpprefs.py:252; путь валидируется `utils.validate_path_in_sysvol` против path-traversal).

Версия GPO: после успешного save/delete `GPODataStore._update_gpo_version(resolved, target)` инкрементирует секцию `[General]` в `GPT.INI`, возвращает `new_version`. RPC-слой `gpo.py` через `_update_ldap_version()` пишет это число в атрибут `versionNumber` объекта GPO в LDAP — чтобы клиенты видели изменение политики.

## 7. Все типы preferences — подробный справочник

### 7.11 Registry — реестр (особый случай)

- **Схема** (gpprefs.py:164): required `hive, key`; optional `action, default, name, type, value, displayDecimal, defaultValue, bitfield, disabled, SubProp`.
- **Валидация** (`_validate_registry_properties`, gpprefs.py:401): hive ∈ {HKEY_LOCAL_MACHINE, HKEY_CURRENT_USER, HKEY_CLASSES_ROOT, HKEY_USERS, HKEY_CURRENT_CONFIG}; action ∈ {U,C,R,D}; bitfield/defaultValue — unsignedByte 0-255; `type` ∈ {REG_SZ, REG_EXPAND_SZ, REG_BINARY, REG_DWORD, REG_DWORD_BIG_ENDIAN, REG_LINK, REG_MULTI_SZ, REG_QWORD, REG_NONE}; `default` и `name` взаимоисключающие.
- **SubProp** — массив `{id, value, mask}` для bitfield-операций, сериализуется в `<Properties><SubProp .../></Properties>` (`_create_subprop_element`, gpprefs.py:871).

> ⚠ **Важно:** `save_preference` с `pref_type="Registry"` возвращает ошибку
> `"Registry preferences must use the 'set' method instead"` (gpprefs.py:962).
> Запись реестра выполняется методом `gpo_set` / `gpo_get_current_value` → `GPTWorker` (`gpui_service/gptworker.py`),
> который пишет бинарный `Registry.pol` (PReg-формат), а **не** XML. Чтение через `get_preferences` при этом
> поддержано: если на диске лежит `RegistrySettings.xml`, он будет распарсен. Для UI-навигации Registry присутствует
> (`tree-view-preferences.js`), но CRUD идёт через отдельный API.

Пример `value` (только для контекста чтения):
```json
{ "hive": "HKEY_LOCAL_MACHINE", "key": "SOFTWARE\\Policies\\App",
  "name": "Enabled", "type": "REG_DWORD", "value": "1", "action": "U" }
```

### 7.12 Общие правила для всех типов

1. **`value`** — JSON-строка. Ключи с префиксом `_` (`_bypassErrors`, `_userContext`, `_removePolicy`, `_desc`, `_status`, `_image`, `_filters`) попадают в атрибуты элемента `<*>`, остальные — в `<Properties>`.
2. **`action`** единый для всех: `U`=Update, `C`=Create, `R`=Replace, `D`=Delete.
3. **`name`** (отображаемое имя) НЕ передаётся клиентом — выводится сервером по `NAME_DERIVE_MAP` (gpprefs.py:274).
4. **Булевы поля** принимают `true/false/0/1/yes/no/on/off` и пишутся в XML как `0`/`1`.
5. **Пути** из `PATH_PROPERTIES` прогоняются через `_escape_path()`: любая серия `\` → `\\` для XML-атрибута.
6. **`disabled`** есть у всех типов — отключает применение элемента.
7. **Фильтры** (`_filters`) item-level targeting едины для всех типов: `{operator:"AND"|"OR", conditions:[{type:"OrgUnit", ...}]}` → `<Filters bool="..."><FilterOrgUnit .../></Filters>`.

## 9. Замечания / открытые вопросы

1. **`Registry`-тип через `save_preference` запрещён** (gpprefs.py:962) — для него используется отдельный метод `set`/`gptworker.py` (`Registry.pol`, PReg-формат). Чтение XML через `get_preferences` поддержано. См. §7.11.
2. **`action: "D"`** в `value` формально проходит валидацию, но фактическое удаление любого preference нужно делать именно через `gpo_delete_preference` (по `uid`), а не save с `action:"D"` — save только пишет/обновляет XML, не удаляет элемент.
3. **`name`** клиентом не передаётся — всегда auto-derived по `NAME_DERIVE_MAP` (gpprefs.py:274). Для типа без правила вывода будет пустая строка.
4. **Фильтры** (`_filters`) item-level targeting сериализуются в `<Filters><FilterType .../></Filters>`; при чтении префикс `Filter` срезается и попадает в `conditions[].type`.
5. **Пароли** (`cpassword`/`password`) шифруются AES-256-CBC по алгоритму Microsoft GPP (`_encrypt_password`, gpprefs.py:716). Применимо к Drives, Printers, ScheduledTasks, Services.
6. **UI-навигация** (`tree-view-preferences.js`) покрывает 8 типов: shortcuts, environment, folders, registry, driveMaps, networkShares, files, iniFiles. Printers, Services, ScheduledTasks доступны только через API/CLI.
7. **Нет примеров** preference-XML в репозитории (`PoliciesData/` содержит только `Registry.pol`/`comment.cmtx`) и нет тестов в `gpuiservice/run_tests.py` для preference-методов — покрытие нужно добавить.
8. **Client-side gap:** `plugin/ui/.../util/API.js` не содержит обёрток `save_preference`/`get_preferences`/`delete_preference`; UI Shortcuts сейчас работает только на `localStorage` с иной схемой (UPPER_CASE enum-int) — требуется mapping-слой для подключения UI к серверу.
