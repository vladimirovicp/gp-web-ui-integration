# ADMX Управление пакетами — Установка/Удаление пакетов

## Постановка задачи

В разделе ADMX "Управление пакетами" есть политики "Установка пакетов" и "Удаление пакетов". Currently в `.gp__admx-wrapper .gp__admx .gp__admx-info` для "Список пакетов для установки" отображается опция "В разработке". Необходимо:

1. Заменить "В разработке" на кнопку "Редактировать"
2. Кнопка "Редактировать" активна только когда состояние политики "Включено", в противном случае не активна
3. При нажатии на "Редактировать" появляется всплывающее окно `.packages-control__modal` (идея из `.preference__modal`)

### Структура модального окна

```
.packages-control__modal
  .packages-control__modal-header
    .title  "Список пакетов для установки" (или "Список пакетов для удаления")
    .close
  .packages-control__modal-content
  .packages-control__modal-footer
    кнопки: New, Delete, Cancel, OK
```

### Поведение кнопок модалки

| Кнопка | Действие |
|--------|----------|
| **New** | В `.packages-control__modal-content` появляется поле (contenteditable div) для ввода пакета. При каждом нажатии — новое поле. |
| **Delete** | Удаляет выделенный (одинарный клик) пакет. |
| **Cancel** | Закрывает модалку, все изменения отбрасываются, остаются предыдущие значения. |
| **OK** | Запоминает введённые данные, отправляются на сервер после нажатия `.button.admx__btn-apply` (Применить). |

### Интерактив полей пакетов

- **Двойной клик** по полю — редактирование (contenteditable div)
- **Один клик** по полю — выделение (подсветка фона синий/серый), после чего можно удалить кнопкой Delete

### Заголовки модалки

- Установка пакетов: `<div class="packages-control__modal-header"><div class="title">Список пакетов для установки</div><div class="close"></div></div>`
- Удаление пакетов: `<div class="packages-control__modal-header"><div class="title">Список пакетов для удаления</div><div class="close"></div></div>`

## Формат данных (серверное API)

### Полный путь данных

```
GET ответ:  {"value_data": ["vim","htop"], "value_type": "REG_MULTI_SZ"}
SET отправка: JSON-строка массива: '["vim","htop","curl"]'
Реестр: REG_MULTI_SZ — null-separated UTF-16LE
```

### Ключи реестра

| Политика | Registry Key | Value Name |
|----------|-------------|------------|
| Установка пакетов (Machine) | `Software\BaseALT\Policies\Packages` | `Install` |
| Удаление пакетов (Machine) | `Software\BaseALT\Policies\Packages` | `Remove` |
| Установка пакетов (User) | `Software\BaseALT\Policies\Packages` | `Install` |
| Удаление пакетов (User) | `Software\BaseALT\Policies\Packages` | `Remove` |

### Серверные файлы

| Файл | Назначение |
|------|-----------|
| `project/freeipa-server-gpo/gpui_service/datastore.py` | DataStore — `set()`, `get_current_value()`, type_map: `list → REG_MULTI_SZ` |
| `project/freeipa-server-gpo/gpui_service/gptworker.py` | Кодирование/декодирование REG_MULTI_SZ (UTF-16LE, null-separated) |

| `project/freeipa-server-gpo/gpui_service/service.py` | D-Bus service layer |
| `project/freeipa-server-gpo/gpui_service/policystate.py` | Policy state manager, type_map |

## Архитектура решения

Скрытый `<input type="hidden">` с `data-policy-type="list"` и `value='["pkg1","pkg2"]'` участвует в системе form-state. Кнопка "Редактировать" — визуальный триггер, открывает модалку. Модалка читает/пишет в hidden input.

### 6. `chain/js/components/templates/admx/admx-template-controller.js`

**Обработчики модалки:**

| Событие | Действие |
|---------|----------|
| Клик на `.packages-control__btn-edit` | Проверить state === 'enabled', читать `JSON.parse(hiddenInput.value \|\| '[]')` → `workingPackages`, рендерить contenteditable div'ы, `modal.classList.add('active')` |

| Клик на "Delete" | Найти `.selected` элемент, удалить его |
| Клик на пакетный div | Toggle `.selected` класса (подсветка фона) |
| Клик на "Cancel" | Закрыть модалку, очистить content |
| Клик на "OK" | Собрать значения из contenteditable div'ов → `hiddenInput.value = JSON.stringify(values)` → trigger `change` event → закрыть модалку |
| Клик на `.close` | То же что Cancel |

`handleStatePolicyChange` уже вызывает `syncControlsWithPolicyState` который disable/enable контролы через `setControlsDisabledState`.

## Ключевые наблюдения

1. Пакетные политики **не имеют** `policyValueEntry` (нет `type: "policyValue"`) — состояние определяется наличием/отсутствием ключа
2. `additive: true` в метаданных — флаг распознаётся парсером, но **не используется** сервером при записи
3. Текущий `parseAdmxCurrentValue` **некорректно** обрабатывает массив из `value_data` — вызывает `parseStringValueAsAdmxState(["vim","htop"])` → `String(array)` → теряет структуру
4. `setControlsDisabledState` запрашивает `.gp__admx-options input, .gp__admx-options select, .gp__admx-options textarea` — нужно расширить для кнопки
