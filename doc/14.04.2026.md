# Документация по сценарию `Policy name -> Edit -> gpo-get-policy -> Result`

## Что было просмотрено

В репозитории найден файл [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js). Предполагаю, что под `pgo.js` имелся в виду именно он.

Дополнительно найден готовый пример вызова `get_policy` в [chain/js/app.js](/E:/git/gp-web-ui-integration/chain/js/app.js).

## Как работает текущий сценарий в `chain/gpo.js`

### 1. Кнопка `Edit` появляется в списке GPO

В описании сущности `gpo` search-facet содержит:

- колонку `displayname` с подписью `Policy Name`
- action `edit`
- кнопку `control_buttons` с `name: 'edit'`

Это задаётся в [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:25) и [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:53).

### 2. Action `edit` регистрируется в FreeIPA UI

В конце файла выполняется регистрация:

- `a.register('edit', exp.edit_action)`
- `e.register({type: 'gpo', spec: exp.gpo_entity_spec})`

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:544).

### 3. При нажатии `Edit` берётся выбранная строка

Метод `exp.edit_action().execute_action()`:

- вызывает `facet.get_selected_values()`
- проверяет, что выбрана ровно одна запись
- берёт имя выбранной политики в `gpo_name = selected[0]`

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:133).

Если записей 0 или больше 1, показывается ошибка:

`Please select exactly one GPO to edit`

### 4. Перед открытием модального окна загружаются текущие данные GPO

Сначала выполняется RPC-запрос:

```js
rpc.command({
    entity: 'gpo',
    method: 'show',
    args: [gpo_name],
    options: {
        version: IPA.api_version
    }
})
```

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:144).

Этот вызов нужен, чтобы получить данные выбранного объекта и открыть диалог уже с заполненными значениями.

### 5. После успешного `show` создаётся модальное окно

Диалог собирается через `IPA.dialog(...)`. В нём создаются поля:

- `displayname` (`Policy Name`)
- `command` (`select`)
- `path`
- `json_data`
- `result`

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:157).

Поле `command` содержит варианты:

- `gpo_get_current_value`
- `gpo_list_children`
- `gpo_set_policy`
- `gpo_get_policy`

Значение по умолчанию:

```js
value: 'gpo_get_policy'
```

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:170).

Поле результата:

```js
{
    $type: 'textarea',
    name: 'result',
    label: 'Result',
    read_only: true
}
```

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:199).

### 6. Показ поля `json_data` зависит от выбранной команды

Функция `updateJsonDataVisibility()`:

- читает выбранную команду из `command_widget`
- если команда не `gpo_set_policy`, скрывает `json_data`
- если `gpo_set_policy`, показывает `json_data`

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:216).

### 7. Кнопка `execute` запускает RPC-команду

Кнопка создаётся так:

```js
dialog.create_button({
    name: 'execute',
    label: 'Execute Command',
    click: function() { ... }
})
```

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:298).

Внутри обработчика:

1. Читаются значения из полей `command`, `path`, `json_data`, `result`.
2. Имя RPC-метода вычисляется из UI-значения:

```js
var method = command.replace(/^gpo_/, '');
```

Пример:

- `gpo_get_policy` -> `get_policy`
- `gpo_set_policy` -> `set_policy`

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:303).

### 8. Для `gpo-get-policy` формируется RPC-вызов

В текущей реализации собираются:

```js
var args = [path];
var options = {
    version: IPA.api_version
};
```

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:313).

Для команды `gpo_set_policy` дополнительно:

- парсится JSON из `json_data`
- результат кладётся в `options.json`

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:319).

Далее выполняется:

```js
rpc.command({
    entity: 'gpo',
    method: method,
    args: args,
    options: options
})
```

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:333).

### 9. Результат попадает в `textarea[name="result"]`

Перед запуском запроса UI показывает:

```js
result_widget.set_value(['Executing...']);
```

После успешного ответа:

```js
var result_data = data.result.result || {};
var json_str = JSON.stringify(result_data, null, 2);
result_widget.set_value([json_str]);
```

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:330).

То есть в `textarea[name="result"]` выводится форматированный JSON из `data.result.result`.

При ошибке:

- показывается `IPA.notify(...)`
- в `result` записывается строка `Error: ...`

См. [chain/gpo.js](/E:/git/gp-web-ui-integration/chain/gpo.js:343).

## Схема работы целиком

```text
Пользователь выбирает строку GPO
-> нажимает кнопку Edit
-> execute_action() получает selected[0]
-> rpc.command({ entity: 'gpo', method: 'show', args: [gpo_name] })
-> on_success создаёт IPA.dialog()
-> пользователь оставляет Command = gpo-get-policy
-> нажимает кнопку execute
-> 'gpo_get_policy' преобразуется в 'get_policy'
-> rpc.command({ entity: 'gpo', method: 'get_policy', args: [path] })
-> data.result.result сериализуется через JSON.stringify(...)
-> строка попадает в textarea name='result'
```

## Важное замечание по текущей реализации

Внутри кнопки `execute` в RPC-запрос передаётся только `path`, а выбранный ранее `gpo_name` туда не передаётся.

Это значит, что текущий код для `gpo-get-policy` опирается только на:

- `entity: 'gpo'`
- `method: 'get_policy'`
- `args: [path]`
- `options.version`

Если в вашем частном случае нужно жёстко привязать вызов к конкретной политике, может потребоваться дополнительно передать `gpo_name` в `args` или `options` в том формате, который ожидает backend.

## Как реализовать частный случай в другом файле и вывести результат в консоль

### Вариант 1. Самый прямой вызов через `rpc.command`

Если в другом AMD-файле уже доступны зависимости `freeipa/ipa` и `freeipa/rpc`, достаточно повторить ту же механику без модального окна:

```js
define([
    'freeipa/ipa',
    'freeipa/rpc'
], function(IPA, rpc) {

    function runPrivateGetPolicy(path) {
        var policyPath = path || '/';

        var command = rpc.command({
            entity: 'gpo',
            method: 'get_policy',
            args: [policyPath],
            options: {
                version: IPA.api_version
            },
            on_success: function(data) {
                var result = (data && data.result && data.result.result) || {};
                console.log('[gpo-get-policy] success:', result);
            },
            on_error: function(xhr, text_status, error_thrown) {
                console.error('[gpo-get-policy] error:', error_thrown || text_status || xhr);
            }
        });

        command.execute();
    }

    return {
        runPrivateGetPolicy: runPrivateGetPolicy
    };
});
```

Что здесь важно:

- `method` нужно указывать как `get_policy`, а не `gpo_get_policy`
- `args` сейчас повторяют логику `gpo.js`, то есть содержат только `path`
- для вывода в консоль достаточно `console.log(result)`

### Вариант 2. Повесить вызов на кнопку в другом файле

Если нужен запуск по нажатию своей кнопки:

```js
document.querySelector('[name="my-run-policy"]').addEventListener('click', function() {
    runPrivateGetPolicy('/');
});
```

### Вариант 3. Использовать уже готовый шаблон из `chain/js/app.js`

В [chain/js/app.js](/E:/git/gp-web-ui-integration/chain/js/app.js:30163) уже есть функция:

```js
function getPolicy(path, onSuccess, onError) {
    var command = rpc.command({
        entity: "gpo",
        method: "get_policy",
        args: [policyPath],
        options: {
            version: IPA.api_version
        }
    });
}
```

И рядом есть обёртка:

```js
function loadMainPolicy(path) {
    getPolicy(path || "/", function(policy) {
        mainPolicy = policy;
        console.log(mainPolicy);
    });
}
```

См. [chain/js/app.js](/E:/git/gp-web-ui-integration/chain/js/app.js:30203).

Если вам нужен просто консольный вывод без UI, это уже почти готовое решение:

```js
loadMainPolicy('/');
```

## Что нужно изменить, если частный случай должен учитывать выбранный `Policy name`

Если backend ожидает не только `path`, а ещё и конкретную политику, используйте схему вида:

```js
var command = rpc.command({
    entity: 'gpo',
    method: 'get_policy',
    args: [gpo_name, policyPath],
    options: {
        version: IPA.api_version
    },
    on_success: function(data) {
        console.log(data.result.result || {});
    }
});
```

Но такой вариант нужно включать только если именно такой формат аргументов поддерживает серверная часть.

## Короткий итог

Текущий сценарий в `chain/gpo.js` работает так:

- выбор строки в таблице даёт `gpo_name`
- кнопка `Edit` открывает модалку
- команда `gpo-get-policy` преобразуется в RPC-метод `get_policy`
- запрос выполняется через `rpc.command(...)`
- ответ берётся из `data.result.result`
- JSON результата отображается в `textarea[name="result"]`

Для частного случая в другом файле вам не нужен весь диалог. Достаточно вызвать `rpc.command({ entity: 'gpo', method: 'get_policy', ... })` и в `on_success` сделать `console.log(...)`.
