# ADMX localStorage removal report

Date: 2026-05-22

## Goal

Remove all ADMX usage of `localStorage` and leave ADMX working only through:

- `API.get_current_value` on open
- `API.set` and `API.deletePolicy` on apply
- in-memory form snapshot for `Apply`/`Cancel`

## Changed files

- `chain/js/app.js`
- `chain/js/components/templates/admx-template.js`
- `chain/js/components/templates/admx/admx-template-controller.js`
- deleted `chain/js/components/templates/admx/admx-storage-state.js`
- deleted `chain/js/util/mainLocalStorage/admx.js`

## Removed ADMX localStorage code

Removed from runtime:

- import of `./util/mainLocalStorage/admx` in `chain/js/app.js`
- call to `initAdmxStorage()` in `chain/js/app.js`
- import of `../../util/mainLocalStorage/admx` in `chain/js/components/templates/admx-template.js`
- reading persisted ADMX entries through `getAdmxEntriesByPaths(...)`
- passing `persistedEntries` / `hasPersistedEntries` into ADMX controller
- import of `../../../util/mainLocalStorage/admx` in `admx-template-controller.js`
- import of `./admx-storage-state` in `admx-template-controller.js`
- write to local storage after successful `Apply` through `upsertAdmxEntries(...)`
- delete from local storage on `not-configured` through `removeAdmxEntriesByPaths(...)`
- fallback restore from local storage when `API.get_current_value` returned empty data
- fallback restore from local storage when `API.get_current_value` failed

Removed files:

- `chain/js/components/templates/admx/admx-storage-state.js`
- `chain/js/util/mainLocalStorage/admx.js`

## Resulting ADMX behavior

- Opening an ADMX policy now loads values only from `API.get_current_value`.
- If the server returns no ADMX values, the form is initialized with default in-memory values.
- If loading fails, the form is also initialized with default in-memory values.
- `Apply` sends only `API.set` or `API.deletePolicy`.
- After successful `Apply`, only the in-memory snapshot is refreshed.
- `Cancel` restores only the in-memory snapshot captured after load or successful apply.

## Manual checks

- Open an ADMX policy with existing server-side values and confirm fields are populated from server data.
- Open an ADMX policy with no server-side values and confirm form starts as `not-configured` with default control values.
- Change ADMX values and click `Apply`; confirm requests use `API.set`.
- Switch policy to `not-configured` and click `Apply`; confirm requests use `API.deletePolicy`.
- Change fields and click `Cancel`; confirm the form returns to the last loaded/applied in-memory state.
- Reload the page after unsaved ADMX edits; confirm unsaved values are not restored from browser storage.
