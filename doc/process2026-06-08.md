## 1. Синхронизация локали

### 1.1 Постановка задачи

При инициализации UI язык браузера может не совпадать с серверной локалью. Необходимо:

1. Определить язык браузера.
2. Запросить текущую серверную локаль.
3. Если они отличаются — установить серверную локаль в соответствии с языком браузера.
4. Подключить модуль переводов для UI.

### 1.2 Маппинг языков

Добавлена функция `mapBrowserToServiceLocale(browserLang)` в `app.js`:

```
browserLang → serviceLocale
ru          → ru-RU
(другие)    → en-US
```

Берётся первые два символа `navigator.language`, приводятся к нижнему регистру.

### 1.3 Новые RPC-методы в API.js

#### `getLocale()`

- Метод: `gpo.get_locale`
- Возвращает текущую серверную локаль (например, `en-US`).
- При ошибке возвращает `en-US` как fallback.

#### `setLocale(locale)`

- Метод: `gpo.set_locale`
- Передаёт целевую локаль как аргумент (например, `ru-RU`).
- Возвращает промис.

#### `getPolicyName()`

- Возвращает кэшированное имя политики (`_policyName`), сохранённое при вызове `initNameGpt(policyName)`.

### 1.4 Порядок инициализации в `app.js`

Функция `init()` переписана с синхронной на промис-цепочку:

```
initNameGpt(policyName)
  → translationsModule.setLanguage(browserLang)
  → API.getLocale()
  → если locale отличается → API.setLocale(targetLocale)
  → initShortcutsStorage()
  → renderHeader / renderMain / renderFooter / resizable
```

Пока промис-цепочка не завершится, UI не рендерится. Это гарантирует, что:

- переводы загружены до рендера;
- серверная локаль синхронизирована до первого RPC-запроса.

## 2. Реструктуризация шапки (header)

### 2.1 Проблема

В предыдущей реализации кнопки ADMX (`Применить`, `Отмена`) и preferences (`Создать`, `Редактировать`, `Удалить`) находились на одном уровне DOM. Это затрудняло управление видимостью групп кнопок при переключении между режимами.

### 2.2 Новая структура DOM

```
gp__header
├── gp__header-left
│   ├── gp__search
│   ├── gp__nav
│   └── gp__control               ← кнопки preferences (Создать/Редактировать/Удалить)
└── gp__control-actions           ← скрыт по умолчанию (display: none)
    ├── gp__control-admx          ← кнопки ADMX (Применить/Отмена)
    ├── gp__control-separator     ← вертикальная линия-разделитель
    └── gp__control-help          ← кнопка «Информация»
```

### 2.3 CSS-изменения

Добавлены стили:

- `.gp__header-left` — flex-контейнер с `overflow: hidden` и `min-width: 0` для корректного сжатия.
- `.gp__control-actions` — `margin-left: auto`, скрыт по умолчанию (`display: none`), показывается через `style.display = 'flex'`.
- `.gp__control-separator` — вертикальная линия 1×24px цвета `#d1d1d1`.
- `.gp__admx-options input[type="checkbox"]` — сброс `opacity` и `position` для корректного отображения чекбоксов.

### 2.4 Управление видимостью

#### При открытии preferences-шаблона (`preferences-view-template.js`)

- `initHeaderButtons()`: `gp__control` показывается (`display: flex`), `gp__control-actions` скрывается (`display: none`).
- `clearHeaderButtonState()`: обе группы скрываются (`display: none`).

#### При открытии ADMX-шаблона (`admx-template-controller.js`)

- `gp__control-actions` показывается (`display: flex`).
- `gp__control` скрывается (`display: none`).
- При нажатии «Отмена» `gp__control` остаётся скрытым.

## 3. Исправления модального окна (`gpo.js`)

### 3.1 Безопасная установка заголовка

**Было:**

```js
'<h4 class="modal-title">GPUI | ' + policyName + '</h4>'
```

**Стало:**

```js
modal.find('.modal-title').text('GPUI | ' + policyName);
```

Заголовок устанавливается через jQuery `.text()` после создания DOM-элемента. Это предотвращает XSS через `policyName`.

### 3.2 Обновление фасета при закрытии

Добавлен вызов `facet.refresh()` в функции `close_modal()`. При закрытии модального окна родительская страница обновляет данные.

## 4. Исправления в ADMX-шаблоне

### 4.1 Условный рендер заголовка description/options (`admx-template.js`)

**Было:** заголовки «Описание» и «Параметры» рендерились всегда, даже если `controlRows` пустой.

**Стало:** заголовок и rows рендерятся только если `controlRows.length > 0`:

```js
...(controlRows.length > 0 ? [
    createElement('div', { className: 'gp__admx-item', ... }),
    ...controlRows
] : [])
```

### 4.2 Алерт при ошибке сохранения (`admx-template-controller.js`)

В блоке `catch` обработчика `handleApply()` добавлен:

```js
alert('Failed to apply policy: ' + (error.message || error));
```

Пользователь видит уведомление, если сохранение завершилось ошибкой.

## 5. Дерево политик (`tree-view-list-data.js`)

### 5.1 Использование имени политики

**Было:** корневой заголовок дерева всегда брался из перевода `t('policies.localGroupPolicy')`.

**Стало:** в `buildTreeViewList()` передаётся `policyName`, и если он задан, используется как заголовок корневого узла:

```js
title: policyName || t('policies.localGroupPolicy')
```

Имя политики получается из `API.getPolicyName()`, который возвращает значение, сохранённое при `initNameGpt()`.

## 7. Возвращаемое значение `init()`

**Было:**

```js
return {
    container, treeViewState, header,
    main, treeView, divider, workspace
};
```

**Стало:**

```js
return { container };
```

Поскольку `init()` теперь асинхронный (возвращает промис), внешний код не может синхронно использовать внутренние объекты. Возвращается только `container`.
